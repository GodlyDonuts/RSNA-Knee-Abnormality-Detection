# Medical encoder source facts

Researched 2026-09-22 by `/root/competition_contract/medical_encoder_sources`; primary sources only. This is source research, not measured RSNA performance. No model weights or datasets were acquired, no training or paid compute was run, and no credentials were accessed. Access/license observations do **not** establish Kaggle eligibility or absence of data overlap. Exact checkpoint revisions must be pinned when artifacts are staged; no claim of locally verified weight loading is made.

## Three candidates to test

### 1. MedSigLIP — strongest first medical 2D comparison

- **Exact release:** `google/medsiglip-448`, model-card version **1.0.0**, created July 9, 2025. Two towers; the image encoder is a **400M-parameter ViT**, native **448×448**, with a separate 400M text encoder. The image tower alone is the relevant classification backbone.
- **Provenance:** image/text pretraining includes chest radiographs, dermatology, ophthalmology, pathology, **CT and MRI slices**, plus natural images. This is a **2D slice encoder**, not a pretrained 3D volume encoder. The published card's evaluation emphasis is CXR/pathology/dermatology/ophthalmology; it does not establish knee pathology performance or disclose knee-specific pretraining composition. [Official model card](https://huggingface.co/google/medsiglip-448)
- **Access/terms:** Hugging Face requires login and acceptance of **Health AI Developer Foundations terms**. The weights are not Apache/MIT merely because supporting code is Apache. Modification and distribution are allowed subject to the agreement; redistribution carries downstream use restrictions, agreement/notice requirements, and modification notices. [Official terms, §§2–3](https://developers.google.com/health-ai-developer-foundations/terms)
- **Experiment inference:** compare native-resolution frozen slice embeddings plus learned series/plane aggregation, then selective tuning if validation improves. MRI exposure makes it plausible; a 400M encoder and many slices make throughput and caching material. No zero-shot knee-label claim is supported.

### 2. BiomedCLIP — smaller, easily specified 2D comparison

- **Exact artifact:** `microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224`, `open_clip_pytorch_model.bin`, with `open_clip_config.json`. The image tower is **ViT-Base/16 at 224×224**; “256” denotes text context, not image resolution.
- **Provenance:** contrastive pretraining on **PMC-15M**, 15 million biomedical scientific figure/caption pairs. This includes heterogeneous publication imagery, not a documented large knee MRI volume collection. An example brain-MRI image in the card is not evidence of knee pathology transfer.
- **Access/terms:** Microsoft’s public Hugging Face card declares **MIT** and provides direct OpenCLIP/local-file loading examples; no acceptance gate was shown. Preserve the applicable MIT copyright/permission notices in redistribution. [Official model card and loading specification](https://huggingface.co/microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224)
- **Experiment inference:** a useful lower-cost medical baseline for the same slice aggregation pipeline. The 224-pixel input and scientific-figure domain may miss subtle ligament/meniscus findings; do not assume “biomedical” implies superiority over a general vision encoder.

### 3. VoCo — available genuine 3D branch

- **Exact first artifact:** author repository `Luffy503/VoCo`, **`VoCo_B_SSL_head.pt`**; official table lists **53M** parameters for this SSL checkpoint. The loading recipe uses **3D SwinUNETR**, `feature_size=48`, one input channel; the full segmentation model and SSL checkpoint have different parameter counts. [Author code/release table](https://github.com/Luffy03/Large-Scale-Medical)
- **Identity:** the Hugging Face file page reports approximately **220 MB** and SHA-256 `06664b629e73a25aacfaf9e0dd3f2df36f93a9f60f0bf8cf4d8b5cc95cd01298`; this is publisher metadata, not a locally recomputed hash. [Official artifact metadata](https://huggingface.co/Luffy503/VoCo/blob/main/VoCo_B_SSL_head.pt)
- **Provenance:** expanded VoCo uses **PreCT-160K: 160K CT volumes / 42M slices**, with geometric-context self-supervision. The paper evaluates transfer to MRI segmentation/registration across multiple organs; its benchmark does not establish knee MRI pathology classification. CT pretraining must not be described as MRI pretraining. [Author paper](https://arxiv.org/html/2410.09890v1)
- **Access/terms:** author-hosted weights and code are marked **Apache-2.0**, with no gate shown. Preserve license/notices and identify modifications when redistributing. [Weight card](https://huggingface.co/Luffy503/VoCo), [repository license](https://github.com/Luffy03/Large-Scale-Medical/blob/main/LICENSE)
- **Experiment inference:** test as a complementary volume encoder, not an assumed winner. Start with the Base SSL artifact; MRI normalization, anisotropic sampling and a classification head need adaptation. Load verification must report matched/missing weights: the sample loader tolerates unmatched keys, so a successful load call alone is insufficient evidence that the encoder was initialized.

## Promising references with unresolved execution constraints

**MedImageInsight (original model, not Premium):** Microsoft’s current Foundry asset is **version 2**, dated September 3, 2026; the release history explicitly says this changed packaging/card details without weight changes. It declares **MIT**, a **360M DaViT image encoder**, and a 252M language encoder. [Official model card](https://ai.azure.com/catalog/models/MedImageInsight?source=microsoft) The paper documents MRI exposure and a small mixed CT/MRI acquisition/view dataset including knees: **1,202 training images across 21 modality/anatomy/view categories**, not 1,202 knee scans. This supports limited knee-view familiarity, not knee injury recognition. [Paper, Appendix A.1 and Table 18](https://arxiv.org/html/2410.06542v1) Current official instructions use an Azure subscription and managed deployment; a verified, pinned Microsoft-origin local checkpoint route was **not established** in this bounded review. Community HF mirrors should not be labeled Microsoft official. Keep this conditional until offline acquisition is confirmed; do not deploy a paid endpoint for this experiment by default. [Official deployment instructions](https://learn.microsoft.com/en-us/azure/foundry-classic/how-to/healthcare-ai/deploy-medimageinsight)

**3DINO-ViT:** exact author model `AICONSlab/3DINO-ViT`, file `3dino_vit_weights.pth`, is gated. Its card describes self-supervision on approximately **100,000 multimodal 3D scans across more than 10 organs**. However, the card applies **CC BY-NC-ND 4.0** and explicitly prohibits modification/adaptation/derivatives and commercial purposes, with an expanded commercial definition. Do not place it on the routine fine-tuning/redistribution plan without resolving those author-stated terms. This is not a claim that a license alone determines competition eligibility. [Official model card](https://huggingface.co/AICONSlab/3DINO-ViT), [official file listing](https://huggingface.co/AICONSlab/3DINO-ViT/tree/main)

**Decipher-MR (2026):** a genuinely MRI-specific 3D ViT-Base (**86M**, 8×8×8 patches), trained using **203,233 series from 22,594 studies**, including knee anatomy, followed by image/text contrastive training. The paper's code-availability section says pretrained weights might not be directly shared because of safety/IP/commercial considerations. No public downloadable checkpoint or weight license was established here; the paper's publication license is not a model-weight license. Therefore this is an informative MRI research reference, not a runnable backbone dependency. Knee inclusion does not demonstrate the competition's 12-label task. [Official publication, Methods and Code availability](https://www.nature.com/articles/s41746-026-02596-4)

The practical recommendation is to add **MedSigLIP, BiomedCLIP and VoCo-Base** to controlled comparisons using the same patient splits and 12-label scoring. This ranking is an engineering judgment informed by provenance/access, not a benchmark result or prediction of leaderboard gain.
