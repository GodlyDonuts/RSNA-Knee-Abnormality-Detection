# Independent review of the high-compute evaluation plan

Prepared by /root/image_pipeline_audit on 2026-09-22. This is a proposed experiment design, not measured performance, purchased labeling, a completed model, or a change to the accepted release. No official gold values, clinical review records or study-level training labels were opened for this review. Counts below come from the existing readiness documentation. Public primary research and code were inspected; no weights or external datasets were downloaded.

The supplied hardware context is UCF Newton with opportunistic availability, many connected two-GPU nodes and InfiniBand; exact available H100 count, memory, quotas and scheduler policies remain unknown. The existing 24-GB rental budget is no longer the appropriate main scheduling assumption. More compute is useful for controlled replication, but the binding limitation remains independent label evidence.

## Findings that should change the plan

1. **Repeated selection is not independent confirmation.** The plan proposes three inner folds, two seeds, a 441-study weak-validation set, coarse blending and cohort checks, but does not specify which result may change the model or when access stops. Repeatedly choosing architecture, losses, crops and blend weights on the same predictions will overfit them. Preregister a limited comparison and selection rule; reserve a final weak-validation comparison and disclose any prior model-result exposure. The 58 historically exposed official studies remain outside model selection and all training, including self-supervised adaptation.

2. **Pooled out-of-fold AUC needs a cross-fold score-scale check.** Pooling creates positive/negative comparisons between predictions from different trained models. Different fold intercepts or score scales can change those comparisons without changing a model's within-fold ranking. Report target-wise within-fold AUC and a predeclared positive-negative-pair-weighted within-fold aggregate, as well as the pooled OOF result. Do not normalize using held-out target labels. Treat disagreement between these summaries as a warning, not permission to choose whichever favors a candidate. Any learned calibration or blend weights require an additional training-only inner split. Five positive fracture studies imply at most five positive groups; the current prose's five-positive-groups statement needs a measured group count.

3. **The release supplies computable AUCs, not adequate rare-target selection power.** Training has 5 fracture, 7 MCL and 9 Baker positives; synovitis has 15 negatives. Three weak-validation targets have one positive. Two seeds, or fifty seeds, do not create new independent examples. Show positive/negative study counts AND leakage-component counts in every fold and target. Leave-one-positive-component-out sensitivity is useful for identifying a fragile ranking; it is not an independent validation dataset. Do not select rare-target specialists or twelve blend weights from these counts.

4. **Report agreement is a different endpoint from image truth.** Missingness is selective, and common explicit normal statements can be report-template or protocol proxies. A model may predict what gets mentioned rather than the intended image finding. Keep the report-supervised development endpoint, but make a separate blinded image-review development audit the highest-value optional labeling expense. Do not turn silence, unresolved correspondence, or an image model's confidence into a negative label.

5. **An encoder comparison currently mixes too many factors.** A frozen DINOv2-S model versus a fine-tuned DINOv3-B or a coarse 3D volume cannot identify whether any benefit came from pretraining, size, slice coverage, spatial resolution, update count or pooling. First compare the same-sized DINOv2-B/14 and DINOv3-B/16 with the same study/series/slice schedule, same 224-pixel field, head capacity and supervision. Then separately test adaptation and spatial detail. Neither natural-image model's published benchmark establishes knee-MRI superiority.

6. **The diagnostic implementation does not yet implement the proposed competitive model.** rsna/model.py is a scratch 2D CNN with one shared slice-attention score and target-specific series attention. rsna/train.py instantiates it directly and performs one optimizer update per loader batch; the proposed pretrained adapters, gradient accumulation, physical position features and frozen-feature pipeline need implementation and acceptance. rsna/data.py repeats/chooses fixed slice slots and exposes plane plus fluid/fat attributes, not a 3D physical coordinate grid. A new experiment entrypoint should consume the same verified release and bind its fold overlay rather than editing accepted split or cache files.

7. **High compute can amplify a spatial-information bottleneck.** Global slice features and 16 sampled slices may discard localized evidence; enlarging a 256-pixel cache does not recover native detail. An inferior global DINO result would not reject its dense features. A separate, preregistered token/local-pooling experiment and a native-detail comparison are needed before rejecting a family. All sampling masks must distinguish padding/repeated positions from independent slices.

8. **Node scaling changes the optimization experiment.** The current masked loss normalizes per target using observed counts in the distributed minibatch. Gradient accumulation of separately normalized microbatches is not generally the same as normalization over the whole effective batch. Preserve and test the intended effective-batch loss when adding accumulation or changing GPU count. Compare actual per-target example exposure, effective batch, optimizer steps and learning-rate schedule, not epochs alone. Resume on a different world size requires a declared policy and equivalence test; exact CPU resume does not establish that property.

9. **Bootstrap confidence has a narrower meaning than the prose suggests.** A paired component bootstrap of fixed predictions measures resampling uncertainty conditional on those fitted models. It does not include all training-seed, fold-design and model-search uncertainty. Keep seed results separate and paired; do not treat seed predictions as additional patients. Count undefined resamples and do not impute AUC=0.5. Model-search correction or a locked confirmation is needed before interpreting a positive interval as decisive evidence.

10. **H100 training does not prove Kaggle inference feasibility.** The final ensemble must be timed on the actual permitted submission environment from raw DICOMs, including decoding, preprocessing and all weights. Pin its offline dependencies before final selection. Current release inputs and bytes remain unchanged; native-detail transforms require new derivative artifacts and acceptance.

## Evaluation protocol that can distinguish the families

Keep the accepted 3,904-study training pool, 441 weak-validation studies, official evaluation and quarantine unchanged. Validate the complete leakage components before constructing experiment folds; every descendant series/crop/feature inherits its study component. Components are a conservative leakage unit, not proven person identity. No test or held-out images enter train-fold MRI self-supervision, report contrastive adaptation, normalization fitting, crop training, feature selection or pseudo-label generation. Deterministic extraction with an unchanged public frozen model may process evaluation images for inference, with no statistic fitted across partitions.

Use the three training-pool group folds for the initial declared candidate comparison. Freeze their exact UID/group membership and observed-class counts before runs. Select learning rates and epoch counts on an inner split within each training fold, or use a fixed schedule chosen before the comparison. Do not select the checkpoint on its outer fold. Restrict early screening to computational failures and a predetermined low-budget schedule; a family cannot be eliminated solely because its frozen representation loses if fine-tuning response is the declared hypothesis.

For finalists, use the same outer folds and seeds for paired comparison. Allocate a minimum of two matched seeds as a variance probe, then additional seeds only if between-seed disagreement threatens the decision. More seeds do not overcome rare-event uncertainty. Keep a fixed evaluation mask and count per target across candidates. Report all twelve targets, the full macro when defined, and a separately named sufficiently-supported-target summary fixed by counts before outcomes. Never substitute a changing available-target mean for the competition macro.

Before viewing the reserved 441-set model results, freeze architecture, input processing, optimizer/epoch policy and a small shortlist. Treat that comparison as report-agreement confirmation with known sparsity. If it triggers changes, record it as development and reserve a new untouched confirmation resource rather than claiming it stayed locked. Official gold remains a one-time predeclared failure diagnostic after model choice, with its legacy exposure stated; no threshold, calibration, architecture or ensemble changes follow its values. Any requested further change must be disclosed as contamination, not relabeled clean evaluation.

For ensemble selection, fit only a coarse global blend inside the development hierarchy. Compare against the strongest single model on a withheld outer fold; do not both fit weights and claim their gain on the same pooled OOF rows. Store each component's OOF predictions with fold and seed identity. An uncertainty interval that crosses zero is inconclusive. Diversity helps only if the predeclared blend improves held-out results at acceptable inference cost.

The official repositories list DINOv2-B/14 and DINOv3-B/16 at approximately 86 million parameters. Patch sizes differ; common 224 input is divisible by both but does not equalize token count or FLOPs. Report both a matched-data/update comparison and a separate fixed-GPU-hour comparison; do not pretend those are the same estimand. Fix the DINOv2 register variant in advance. These are published model characteristics, not MRI performance evidence. [DINOv2 official models](https://github.com/facebookresearch/dinov2), [DINOv3 official models](https://github.com/facebookresearch/dinov3).

DINOv3's dense representation is a reason to test local pooling, not a claim of superiority for this task. Pin its exact weights, code and license before use. Its access/license differs from the original DINOv2 models; variants added to either repository can have distinct terms. [DINOv3 paper](https://arxiv.org/abs/2508.10104), [DINOv3 license](https://github.com/facebookresearch/dinov3/blob/main/LICENSE.md).

For 3D, build each volume from its actual ordered positions, spacing and orientation; validate gaps and coverage. Do not stack different series as consecutive slices or infer registered cross-series channels from equal shapes. Prefer anisotropy-aware processing, and record any resampling. Swin UNETR's cited pretraining used 5,050 CT images; those weights are a CT-transfer comparator, not established MRI pretraining. No specific external MRI checkpoint has been admitted by this review. [Swin UNETR primary paper](https://arxiv.org/abs/2111.14791). The knee-specific MRNet study motivates a strong 2D series baseline but does not validate the current twelve-target severity task. [MRNet study](https://journals.plos.org/plosmedicine/article?id=10.1371/journal.pmed.1002699).

## Rare-target label budget

Spend any authorized image-review budget on independent information before repeating the existing few positives. This is a proposed allocation by expert time, not permission to purchase services or alter the release. Pilot review time and yield before committing case counts.

A reasonable initial allocation is 40% to a probability-sampled, blinded development audit; 40% to targeted training-pool acquisition; and 20% to a second independent reader and disagreement adjudication. Each lane must include independently assessed present, absent and indeterminate states under the exact rubric. If complete twelve-target reads are cost-effective, prefer them to isolated labels so the same image review informs several bottlenecks. Time percentages are starting choices, not a statistical optimum.

The probability sample must be chosen without model errors or clinical outcomes and separated by component before review. It supplies an honest check of silent/masked cases and weak-label selection bias. Keep it unavailable to training and final model selection until its role is fixed. A separate outcome-enriched challenge set can measure behavior on difficult rare cases, but it is not a population performance estimate. Record sampling probabilities and spectrum, and do not quietly mix active-selection cases into the random audit.

Training acquisition priorities are (1) independently confirmed fracture, MCL and Baker positives across distinct components; (2) independently confirmed synovitis negatives, its opposite imbalance; (3) positives and close rubric boundaries for lateral OA, effusion and other sparsely supported targets. Include controls and disagreements, not only high-confidence model hits. Report proxies or train-only OOF disagreement can rank candidates for expert review; they cannot supply the answer. For a frozen outer-fold experiment, any model-driven acquisition must use only that fold's training data. An independent uniform acquisition made before splitting has a different and explicitly recorded provenance.

Set a pilot stopping rule based on review yield, reader agreement, independent positive/negative components and the uncertainty of planned comparisons. Do not promise that an arbitrary number such as 50 positives guarantees adequate power. Rare-target group bootstrap and leave-one-group sensitivity should inform a prospective sample-size decision. Preserve unresolved correspondence and semantic holds until their specific evidence requirement is met; new image labels belong in a separately versioned policy, never as silent edits to originals. Do not manually label hidden/public-test examples or official evaluation studies for training or submission fitting.

## Newton execution and stop decisions

First inspect actual allocated GPUs, memory, interconnect, scheduler wall-time/preemption rules, local scratch and shared-filesystem throughput. Run a representative end-to-end pilot with the real study graph, including long-series cases. Measure data stalls, peak memory, optimizer seconds, epoch time and raw-source inference separately. Use BF16 only after model and gradient checks; preserve the precision configuration in every checkpoint.

Schedule independent fold, seed or ablation jobs on available two-GPU nodes. Benchmark one GPU versus intra-node DDP at the same effective batch and exposure; use two independent one-GPU jobs when that yields more completed comparisons. InfiniBand makes cross-node experiments possible, not automatically efficient. Reserve cross-node training for a measured single-job bottleneck; most scientific value here is in matched independent experiments.

Use CPU capacity for validated decoding/reprocessing, deterministic pack/index creation, bootstrap calculations and artifact verification. Write derivatives in new sharded locations with source/transform hashes, then stage immutable read caches on node-local scratch. Avoid many jobs repeatedly decompressing the same NPZ over shared storage. A frozen feature cache must bind weight, preprocessing, source/series selection and feature dtype; fine-tuned features cannot reuse it. Do not duplicate the full source tree on the nearly full laptop.

Persist model, optimizer, sampler, scaler and random states with fold/UID/weight/source hashes to durable storage. Checkpoints are atomic and distinct by experiment; interrupted work resumes rather than starts a new unlogged seed. Preemption and changed-world-size behavior need tests. Budget GPU-hours from measured time per study, actual fold size, epochs and seeds, adding pretraining and retries explicitly; no node count or free capacity is assumed.

Stop broad model search if small matched experiments cannot separate candidates on supported labels or expose a supervision/coverage limitation. Redirect effort to independent labels, physical input quality or a predefined complementary representation. Promote larger models only for reproducible held-out benefit per GPU-hour and acceptable final offline runtime. No part of this memo changes accepted source bytes, labels, masks, cache, model code or release gates.
