No GPU, Dataset, entry, remote compilation or launch has run for this adapter.

The original pointwise qualification charged 450.798 GPU-VM seconds. Its exact compiler runs the two T4 loops sequentially. This adapter overlaps those two loops, retaining all 32 original studies on each GPU, both 94-window views, exact original input hashes, CPU/GPU input equality, complete learned-state equality and the original `1e-6` served-versus-training probability bound. It changes no model operation, checkpoint, study coverage or competition inference.

`adapter.adapt(original_qualification, compiler_source=original_compiler)` requires the exact final ranking source `69f0d913…`, model lineage `d478a502…` and original compiler `9b179868…`. It returns a distinct source and explicit adapter/source hashes. Only `_adapted_qualify` changes; all bytes outside that definition remain intact. The original compiled qualification and active or completed owners must be retained.

Each worker has its own CUDA device context, `no_grad` context, model/reference graphs and tar handle. The outer function's `no_grad` decorator alone would not cover worker threads. Each device still independently decodes and verifies every case. Exceptions propagate, both workers are joined, handles close and model references are released. Per-device startup, preparation, training-graph forward, serving-graph forward and each study's elapsed times are recorded. The function also records its total elapsed time. These timings explicitly exclude VM startup, top-level imports and the preceding `_adapted_boot`.

The integration point is **after reading and hashing the original node-local ranking `qualification.private.py`, before writing a distinct newly compiled qualification source**. The exact private parent source stays on its owning node. A separate operational adapter must bind the new qualification SHA/slug and its accepted adapter metadata in the canonical ledger and Dataset/source preparation.
