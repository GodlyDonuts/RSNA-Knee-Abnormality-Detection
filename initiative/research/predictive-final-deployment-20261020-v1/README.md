# Predictive final deployment: prepared, not dispatched

Local controls for the **actual completed B/C/C0 six-epoch, 2,916-update,
3,887-study** production models. No Dataset, GPU notebook, entry, transfer,
remote CPU allocation or new background owner has been started by this work.
The original fitting/cache/source-zero owners remain responsible for their work.

This is a deployment path, not an accuracy result. Actual completed training,
independent private five-object final publication, and trained T4 qualification
are still required. The earlier fresh-head T4 probe cannot substitute for them.

## Concrete phases and bindings

`run_once.py` performs one explicitly requested CPU phase, using the original
stdin-only SSH transport. It has no loop or background owner. All own controls
and serving sources are read from one explicit committed `--source-git`; the
stage freezes them, including the unchanged canonical workflow and corrected
GPU-capacity helper. Credentials are read from ignored mode-0600 `.env` only for
account phases and travel through stdin. Public source, private parent
constructor text and checkpoints are never printed.

1. **stage** creates a unique node-local
   `/tmp/rsna-predictive-final-deployment-20261020-v1-<identity>` control root,
   only after separately admitted fresh storage funding.
2. **prepare** reads each original `run_root/terminal.json`, the actual original
   Slurm parent `COMPLETED 0:0`, and `publication/epoch-006/verified.json`.
   Every final publication object is bound to the actual recipe, input,
   accepted source, initialization, lineage and job. It copies the exact three
   model-only exports and their original metadata into one private payload and
   makes one stored ZIP. It never retrains, republishes to HF, or downloads those
   already verified HF objects again.
3. **dataset** creates one private Dataset version 1 under the canonical Newton
   claim and ledger. Its slug is
   `godlydonuts/rsna-predictive-finals-<bundle_identity[:12]>`, independently
   determined by all three final models, original publication receipts and
   actual terminal bindings. A durable local and canonical intent precedes
   the single create RPC. **dataset-reconcile** independently streams every
   Dataset object through full size/SHA checking without storing another
   download. Repeating a completed verification checks immutable metadata;
   it does not download everything again.
4. **compile --mode qualification** runs the existing final-serving CPU
   compiler with the actual verified `model_dataset_ref`. The original public
   parent Dataset `nartaa/rsna-knee-publication-swa-weights-20261007`,
   ID **12431568 v1**, is reused. Required exact model filenames are
   `predictive-B-epoch-006.pt`, `predictive-C-epoch-006.pt`,
   `predictive-C0-epoch-006.pt`.
5. **push/status --mode qualification** performs one combined, sequential-arm
   B/C/C0 trained FP16/FP32/cross-T4 numerical and memory qualification. It
   preserves actual input/render/inference timing. No qualification CSV or
   competition entry is produced.
6. After an explicit engineering decision on that actual timing, **compile,
   push, status --mode B|C|C0** separately build and run each useful final
   competition code version. The exact worker, helper, model, Dataset, Docker,
   offline settings and three-study output CSV are checked. Public CSV bytes
   are independently downloaded and checked in RAM. They are never uploaded

7. **submit --mode B|C|C0** checks fresh authoritative daily allowance, existing
   canonical intents and exact code version, then calls `CreateCodeSubmission`

## Incremental storage admission

This work does **not** spend the previously reserved 60 GiB training or 574 MiB
other obligations. Its new reservation is:

| Location | Incremental reservation | Purpose |
|---|---:|---|
| Owning node `/tmp` | **2 GiB** | At most three 340 MB model copies + one stored ZIP, original small metadata, controls, receipts |
| Shared storage | **1 MiB, 8 files** | Existing canonical ledger growth and transient claim/SQLite journal allowance |
| Verification RAM | Streaming 4 MiB blocks | Full Dataset verification; no additional disk download |

There are no shared model, source, ZIP or job-log files. `srun` output returns
over SSH. At the maximal accepted model size, two copies of all three models
cost 2,040,000,000 bytes; the remaining 107,483,648 bytes cover metadata and
controls. The implementation checks the entire new node-local root against
2 GiB. Fresh free space must preserve the 20 GiB shared/node floor and
5,000 shared-file floor **after all other outstanding obligations and this new
reservation**. Only bytes physically charged in this exact new root reduce
its own future obligation. No deleted originals or hypothetical retired
liabilities supply credit.

The original complete model exports must be present on the selected owning
node. These controls do not invent a cross-node copy or fund one. A verified
Dataset with a ZIP wrapper is retained, but compilation blocks until its exact
relative model paths are admitted; it never scans the complete competition tree
to guess a mount.

## Runtime decision and limitations

Fresh live quota follows the already corrected original CPU969788 accounting:
`totalTimeAllowed - timeUsed - timeReserved`. `minimumTimeAllowed` is not the
account's maximum grant. No billing settings are changed and no paid credit is
requested. The caller must include the actual remaining obligations of other
jobs; they cannot be retired by assumption.

One combined qualification cap (at most 1,800 seconds), the remaining independent
600-second public executions and all other active reservations must fit the
actual unreserved grant before a push. Competition notebooks retain a
32,400-second session limit; the worker's 600-second watchdog applies only to
the exact original public UID roster.

The policy reports measured mean two-lane, maximum-public-case two-lane, and
explicit tail-sensitivity scenarios. The planning count is an assumption with
a written basis; **3,887 training studies is not the hidden-test count or a
known upper bound**. There is no invented mandatory 3×/7.5-hour veto. An entry
decision must cite the exact optimized trained qualification receipt, select a
scenario, state a rationale and safety margin, and fit the actual nine-hour
limit under that selection. Three public studies cannot prove unseen-volume
tails or hidden runtime.
