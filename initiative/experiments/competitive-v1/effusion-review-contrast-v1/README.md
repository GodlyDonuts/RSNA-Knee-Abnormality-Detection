# Reviewed fitting supervision: strict control versus Effusion recovery

This is the first contrast selected after the owner's October3 research program.
It tests whether explicitly reviewed masked report evidence helps, with the images
and model held fixed. It does not assume all report omissions are negatives or
all source-positive cases meet image-derived competition thresholds.

## Actual code

The canonical trainer accepts an optional `fitting_supervision` policy:

```json
{
  "kind": "effusion_review_v1",
  "sha256": "936e3e2af058726fe3572b7e4ad1680c44f2fd82ad6e9840e2607a1b090ff018",
  "enabled": false
}
```

The candidate changes only `enabled` to `true`. Both arms pass the exact private
proposal with `--fitting-supervision`; no machine-specific path enters numerical
bindings. Both validate the same complete original2247/1156 fold0 rosters and
review/hold/source/release hashes BEFORE a diagnostic subset. Control uses the
original16 positive Effusion masks; candidate changes exactly31 fitting cells,
with47 observed positives. The entire outer frame and other target/provenance
columns stay unchanged, and the release/registry is never rewritten.

The policy and actual receipt bind all checkpoints, update journals, terminal
results and resume. A resumed run cannot silently change the arm, artifact or
membership. Absent policy preserves old numerical config serialization. Historical
checkpoints still require their exact original source; changed code does not
replace remote C9 libraries. Initial RNG/model construction is unaffected by the
in-memory input admission. Both arms keep the original MRI-only head and sigmoid.
Competition inference explicitly rejects these experimental-supervision weights;
research performance is not automatic deployment admission.

The first contrast requires outer-fold scope and excludes witness/relation changes
or Stanford initialization. No simultaneous model intervention. The original
[standalone loader proof](../../../audits/effusion-fitting-overlay-loader-v1/README.md)
and [independent report review](../../../audits/effusion-focused-reliability-v1/expanded-review-v1/README.md)

## Scientific acceptance

Before fitting, accept actual pinned official-weight MRI full/stop1/resume on an
allocated GPU for both arms with unchanged input views, initial learned state,
complete optimizer/counters/RNG and byte-identical resumed predictions. Local
synthetic tests do not satisfy this. Require explicit source/environment/base/
fold/license bindings and fresh checkpoint/publication/storage funding. No new
GPU reservation was made for this integration.

The prepared `control-screen.json` and `candidate-screen.json` differ only in
the enabled arm. They preserve the original native384 fold0 recipe and declare
three epochs/843 updates, original141-update warmup and cosine schedule. They
are validated local configs, not funded or dispatched jobs. Engineering must
include actual reviewed positive cells, not an arbitrary tiny prefix that never
exercises the changed masks.

Use this isolated fixed-budget screen, then a separately funded ten-epoch comparison
if warranted; do not select the best epoch. Screen endpoints and gradient inspection
must be fixed before dispatch. Hold uniform slice sampling, original model/input,
head/encoder seeds, full fitting and outer membership, effective batch8, optimizer
and schedule identical. Record actual image presentations and elapsed GPU time.
Effusion is the predeclared primary outcome; all12-target macro remains secondary.
Report paired whole-leakage-component uncertainty and undefined draws. The original
outer weak labels are selective, so interpret both positive and null outcomes
accordingly. Replicate a promising result on separately admitted evidence; protected
gold/confirmation stay unused. Never claim a clinically correct image label from
report agreement alone.
